# ADR-025 — M9.3 Real Two-Executor Hot Local Handoff Proof Contract Lock

STATUS: LOCKED

## Context

ADR-023 / TASK-034 proved the immutable dirty-workspace checkpoint primitive (M9.1).

ADR-024 / TASK-035 proved the Human-authorized Bridge prepare/activate lifecycle (M9.2).

M9.3 now proves that two real, distinct Executor frontends can continue the same unpublished dirty task workspace across that lifecycle and publish one auditable result.

M9.3 is a proof milestone. It MUST NOT redesign M9.1/M9.2, lease semantics, stable-boundary failover, routing, or provider policy.

## Decision 1 — Exact real proof actors

The canonical M9.3 proof pair is:

```text
SOURCE_EXECUTOR: codex
REPLACEMENT_EXECUTOR: antigravity
```

The Human must explicitly select both actors at their respective authority boundaries.

No automatic fallback, quota router, alias, worker string, or inferred actor is acceptable proof.

If either real frontend is unavailable, the proof stops. A substitute pair requires a new explicit proof contract/review decision.

## Decision 2 — Exact unpublished continuity boundary

The proof must cross a real unpublished dirty-workspace boundary.

Before `hot-handoff-prepare`, Codex creates exactly one source-stage payload:

```text
proofs/TASK-036-M9/source-stage.txt
```

No commit/push/publication may occur before handoff preparation.

The source checkpoint must therefore bind:

```text
HEAD == TASK-036 baseline main SHA
source_executor_id == codex
source-stage.txt present in checkpoint manifest
replacement-stage.txt absent from checkpoint manifest
```

## Decision 3 — Exact hot-handoff scope marker

TASK-036 contains exactly one machine-readable marker:

```text
HOT_HANDOFF_ALLOWED_PATHS_JSON: ["proofs/TASK-036-M9/source-stage.txt"]
```

At checkpoint time the dirty workspace must contain only that allowed source-stage path.

The source Executor must not pre-create replacement-stage evidence, verifier code, tests, or final proof artifact before checkpoint capture.

## Decision 4 — Human-controlled lifecycle

The only accepted proof sequence is:

```text
Human approve TASK-036 RUN --executor codex
  ↓
Codex creates source-stage.txt only; STOP
  ↓ Human confirms quiescent
bridge.py hot-handoff-prepare 36 --confirm-quiescent
  ↓
HANDOFF_PREPARED / zero active lease / exact checkpoint fp
  ↓ Human explicitly selects replacement
bridge.py hot-handoff-activate 36 --executor antigravity --checkpoint <exact-fp>
  ↓
Antigravity reads bridge.py context 36
  ↓
Antigravity creates replacement-stage evidence + verifier + tests
  ↓
verifier emits mechanical proof JSON
  ↓
Bridge publish full suite
  ↓
RESULT-036 with HOT_HANDOFF: YES
  ↓
ChatGPT independent audit
```

Human remains sole authority for RUN, prepare confirmation, replacement activation, and MERGE.

## Decision 5 — Replacement-stage proof payload

After activation, Antigravity must create:

```text
proofs/TASK-036-M9/replacement-stage.txt
```

The replacement-stage payload must be absent from the source checkpoint and present in the final published commit.

This is the mechanical witness that the replacement Executor performed new workspace mutation after activation rather than merely publishing the source Executor's dirty state unchanged.

## Decision 6 — Mechanical proof harness

M9.3 uses a thin verifier:

```text
scripts/aios_m9_real_hot_handoff_proof.py
```

and focused tests:

```text
tests/aios_bridge/continuity/test_m9_real_hot_handoff_proof.py
```

The verifier may READ the existing Bridge authorization/lease/checkpoint objects. It must not acquire/release leases, mutate authorization, call external models, commit, push, or select actors.

The verifier emits:

```text
proofs/TASK-036-M9/PROOF.json
```

## Decision 7 — Required proof bindings

`PROOF.json` must mechanically bind at minimum:

```text
schema_version
TASK-036
baseline/head SHA from checkpoint
checkpoint_fingerprint
workspace_id
source_executor_id = codex
source_lease_fingerprint
source_execution_fingerprint
replacement_executor_id = antigravity
replacement_lease_fingerprint
replacement_execution_fingerprint
authorized artifact path/blob
allowed_paths
canonical checkpoint object
source-stage path/hash/size from checkpoint
source-stage current path/hash/size
replacement-stage path/hash/size current
replacement-stage absent from checkpoint manifests
current task branch
```

The proof fingerprint must be SHA-256 of deterministic canonical semantic JSON excluding only its own fingerprint.

## Decision 8 — Verifier trust boundary

The verifier must load the exact checkpoint only by the ACTIVE authorization's exact hot-handoff checkpoint fingerprint and exact content-addressed runtime path.

Forbidden:

- scanning checkpoint history;
- latest/nearest checkpoint selection;
- accepting caller-supplied checkpoint bytes as authoritative;
- free-form log parsing;
- actor inference from text;
- worker-name heuristics.

It must reconstruct and require the exact currently ACTIVE replacement lease before emitting proof.

## Decision 9 — Source-stage preservation

At verification time:

- `source-stage.txt` must exist in the checkpoint tracked/untracked manifest;
- its current bytes must still match the checkpoint manifest hash and size;
- it must remain present in the final publication.

Replacement may not overwrite/delete the source witness.

## Decision 10 — Replacement-stage novelty

At verification time:

- `replacement-stage.txt` must NOT exist in either source checkpoint manifest;
- it must exist now as a regular UTF-8 text file;
- its SHA-256 and size are bound into `PROOF.json`.

This proves a post-checkpoint workspace contribution exists.

## Decision 11 — Bridge RESULT is independent lifecycle evidence

Normal M9.2 Bridge publication remains authoritative for lifecycle actor identity.

The final RESULT-036 must contain exactly compatible evidence:

```text
ACTION: RUN
EXECUTOR_ID: antigravity
EXECUTOR_FAILOVER: NO
HOT_HANDOFF: YES
HOT_HANDOFF_CHECKPOINT_FINGERPRINT: <same fp as PROOF.json>
HOT_HANDOFF_FROM_EXECUTOR: codex
HOT_HANDOFF_TO_EXECUTOR: antigravity
```

`PROOF.json` and RESULT-036 must agree exactly on actor IDs and checkpoint fingerprint.

## Decision 12 — Stable failover separation

M9.3 must not create or reuse:

```text
StableExecutorFailoverProof
M6 failover proof
M8 composite failover proof
```

`EXECUTOR_FAILOVER` must remain `NO` for the M9.3 proof publication.

## Decision 13 — Allowed implementation scope

M9.3 implementation/proof files are limited to:

```text
scripts/aios_m9_real_hot_handoff_proof.py
tests/aios_bridge/continuity/test_m9_real_hot_handoff_proof.py
proofs/TASK-036-M9/source-stage.txt
proofs/TASK-036-M9/replacement-stage.txt
proofs/TASK-036-M9/PROOF.json
.ai/results/RESULT-036.md   # Bridge-generated only
```

No M9 core source or Bridge lifecycle modification is required or authorized.

## Decision 14 — Required adversarial verifier coverage

Tests must reject at minimum:

1. missing/malformed active authorization;
2. authorization not ACTIVE;
3. no hot-handoff metadata;
4. source actor != codex;
5. replacement actor != antigravity;
6. source == replacement;
7. active lease mismatch;
8. exact checkpoint file missing/tampered;
9. checkpoint fingerprint mismatch;
10. checkpoint task/branch/workspace/provenance mismatch;
11. source-stage absent from checkpoint;
12. source-stage hash/size drift after handoff;
13. replacement-stage already present in source checkpoint;
14. replacement-stage missing after activation;
15. replacement-stage binary/non-UTF-8/symlink/unsafe path;
16. proof fingerprint tamper;
17. no history scanning/fuzzy fallback.

## Decision 15 — Acceptance boundary

M9.3 PASS proves one real two-Executor unpublished continuity chain:

```text
codex dirty contribution
   -> M9 checkpoint
   -> zero-active prepared boundary
   -> antigravity activation
   -> antigravity new contribution
   -> one Bridge publication
```

PASS does not imply automatic routing, provider equivalence, multi-machine handoff, or arbitrary Executor-pair proof.
