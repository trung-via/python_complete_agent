# ADR-028 — M10.3 Real Operational Dispatch Proof Contract Lock

STATUS: LOCKED

## Context

M10.1 established a pure, deterministic, zero-token recommendation policy. M10.2 connected that policy to explicit external runtime capacity observations and a read-only Bridge recommendation surface while preserving the invariant:

```text
RECOMMENDATION != AUTHORIZATION
```

M10.3 must now prove the complete real operational chain on one real task without redesigning M10.1 or M10.2:

```text
real runtime capacity evidence
  -> real Bridge recommendation
  -> no authority mutation by recommendation
  -> Human explicit executor authorization
  -> exact active ExecutorLease
  -> selected Executor performs task work
  -> Bridge publication
```

This milestone proves AIOS dispatch behavior, not the vendor's internal quota accounting system. `HUMAN_DECLARED` capacity means the Human attests the observed runtime condition; M10.3 proves how AIOS consumes and acts on that explicit observation.

## Decision 1 — Scope Is Proof Only

M10.3 SHALL NOT redesign or modify production M10.1/M10.2 semantics.

Forbidden production changes include:
- `src/aios_bridge/continuity/dispatch.py`;
- `src/aios_bridge/runtime_dispatch.py`;
- `bridge.py`;
- Brain/Executor core contracts;
- lease/failover/hot-handoff contracts;
- providers or External Brain API code.

M10.3 may add only a task-specific verifier, adversarial tests, proof artifacts, and Bridge-generated RESULT.

## Decision 2 — Canonical Real Actors

The canonical proof scenario is:

```text
EXHAUSTED_EXECUTOR: antigravity
SELECTED_EXECUTOR: codex
ACTION: RUN
CAPACITY_SOURCE: HUMAN_DECLARED
ALLOW_PAID_API: false
```

The authoritative TASK policy SHALL contain exactly the two Executor candidates needed for this proof:
- `antigravity`, preference rank 0;
- `codex`, preference rank 1.

Both SHALL declare the required repository/filesystem/shell/test/local-git capabilities for RUN.

The proof must observe:

```text
antigravity = QUOTA_EXHAUSTED (fresh)
codex       = AVAILABLE       (fresh)
```

The expected deterministic recommendation is exactly:

```text
STATUS: SELECTED
SELECTED_EXECUTOR: codex
HUMAN_APPROVAL_REQUIRED: YES
AUTHORIZATION_CHANGED: NO
LEASE_CHANGED: NO
```

If the real observation is no longer true before capture, the Human MUST NOT falsify it. The proof run must stop and the control artifact must be reconsidered.

## Decision 3 — Recommendation Must Exist Before Authorization

A successful real `bridge.py recommend 39 --kind executor --action RUN` invocation SHALL be captured before Human RUN authorization.

The raw stdout receipt SHALL live outside the Git worktree at the exact runtime-relative path:

```text
dispatch/proofs/TASK-039/recommendation.txt
```

The capture operation SHALL fail closed if that receipt path already exists. No history/latest/glob/fuzzy receipt lookup is allowed.

The receipt is evidence only. It does not grant execution authority.

## Decision 4 — Exact Recommendation Receipt Binding

The task-specific verifier SHALL parse the raw Bridge receipt fail-closed and require exactly one occurrence of each scalar field:

```text
TASK_ID
ACTION
AUTHORIZED_ARTIFACT_PATH
AUTHORIZED_ARTIFACT_BLOB_SHA
POLICY_FINGERPRINT
CAPACITY_OBSERVATION_FINGERPRINTS
DISPATCH_REQUEST_FINGERPRINT
DISPATCH_RESULT_FINGERPRINT
STATUS
SELECTED_EXECUTOR
HUMAN_APPROVAL_REQUIRED
AUTHORIZATION_CHANGED
LEASE_CHANGED
```

It SHALL require:

```text
TASK_ID: TASK-039
ACTION: RUN
AUTHORIZED_ARTIFACT_PATH: .ai/tasks/TASK-039.md
STATUS: SELECTED
SELECTED_EXECUTOR: codex
HUMAN_APPROVAL_REQUIRED: YES
AUTHORIZATION_CHANGED: NO
LEASE_CHANGED: NO
```

It SHALL parse deterministic `CANDIDATE_EVIDENCE` JSON lines and require exact evidence for `antigravity` and `codex` only.

No recommendation fact may be inferred from prose, RESULT history, prior authorization, actor aliases, or nearest/latest artifacts.

## Decision 5 — Recompute Recommendation From Current Exact Evidence

While the TASK-039 RUN authorization and lease are active, the verifier SHALL:
1. load the exact authoritative TASK policy marker;
2. load exact current runtime capacity records for `antigravity` and `codex`;
3. require both records fresh;
4. require stored/effective states exactly `QUOTA_EXHAUSTED` and `AVAILABLE` respectively;
5. require record fingerprints equal the receipt fingerprints;
6. build the existing M10.1 request using existing M10.2 helpers;
7. call existing `dispatch_executor()`;
8. require policy/request/result fingerprints equal the receipt;
9. require the recomputed selected actor to be exactly `codex`.

The verifier SHALL NOT contain a second ranking algorithm.

## Decision 6 — Causal Ordering Evidence

The proof SHALL bind real local ordering using exact runtime files:

```text
capacity record mtimes <= recommendation receipt mtime <= authorization file mtime
```

Equality is permitted for filesystem timestamp granularity.

The verifier SHALL reject if:
- receipt is missing;
- receipt is a symlink/non-regular file;
- receipt resolves outside the expected runtime proof directory;
- receipt mtime is after the RUN authorization file mtime;
- either capacity record mtime is after the recommendation receipt mtime.

This ordering evidence supplements, but does not replace, M10.2's already-proven read-only recommendation contract.

## Decision 7 — Human Authorization Is Separate and Exact

After the recommendation receipt exists, only the Human may authorize RUN:

```text
bridge.py approve 39 --kind task --executor codex
```

The verifier SHALL require the exact current authorization to be:

```text
status: ACTIVE
task_id: TASK-039
action: RUN
executor_id: codex
artifact_path: .ai/tasks/TASK-039.md
artifact_blob_sha: exact TASK-039 blob
target branch: ai/task-039
```

No executor identity may be inferred from recommendation alone.

The verifier MUST reject missing/CONSUMED/cancelled/wrong-action/wrong-executor/wrong-artifact authorization.

## Decision 8 — Exact Active Lease Binding

The verifier SHALL reconstruct the expected `ExecutorLease` from the ACTIVE authorization and call the existing exact active-lease validation path.

It SHALL require:
- executor `codex`;
- operation `RUN`;
- exact TASK-039/workspace binding;
- exact lease fingerprint;
- exactly the authorization-bound active lease.

No lease creation, release, repair, fallback, or inference is allowed in the verifier.

## Decision 9 — Executor Stage Witness

After Human authorization, Codex SHALL create exactly one canonical executor witness:

```text
proofs/TASK-039-M10/executor-stage.txt
```

Exact bytes:

```text
TASK_ID: TASK-039
STAGE: HUMAN_AUTHORIZED_EXECUTION
EXECUTOR_ID: codex
RECOMMENDED_EXECUTOR_ID: codex
ACTION: RUN
PAYLOAD_VERSION: 1
```

with exactly one final newline.

The verifier SHALL require exact bytes and bind its SHA-256.

The witness MUST NOT exist in the pre-authorization recommendation receipt path and MUST be created only after Human authorization has prepared the task branch.

## Decision 10 — Canonical Proof Artifacts

The verifier SHALL copy the validated raw external receipt byte-for-byte into:

```text
proofs/TASK-039-M10/recommendation-receipt.txt
```

and emit:

```text
proofs/TASK-039-M10/PROOF.json
```

`PROOF.json` SHALL bind at minimum:
- schema version;
- task ID / branch / baseline SHA;
- exact TASK path + blob SHA;
- exact recommendation receipt SHA-256 and runtime mtime;
- policy/request/result fingerprints;
- exact selected executor;
- full validated capacity record snapshots + fingerprints + mtimes;
- exact ACTIVE authorization semantic snapshot + authorization file mtime;
- exact reconstructed ExecutorLease snapshot + fingerprint;
- executor-stage path + SHA-256;
- causal-ordering facts;
- deterministic proof fingerprint.

The proof fingerprint SHALL be SHA-256 of canonical semantic JSON excluding only the `proof_fingerprint` field itself.

The verifier SHALL atomically write PROOF.json and validate read-back semantics.

## Decision 11 — Verifier Authority Boundary

`scripts/aios_m10_real_dispatch_proof.py` is a verifier/proof emitter only.

It MUST NOT:
- call `approve` or `handoff`;
- create/update authorization;
- acquire/release/repair a lease;
- invoke an Executor or Brain;
- call an LLM/provider/API;
- mutate capacity observations;
- run `bridge.py recommend` on behalf of the Human;
- commit/push/merge;
- scan history/latest/globs for alternate recommendation evidence.

It MAY read exact Bridge/runtime evidence and write only the task proof artifacts listed by this ADR.

## Decision 12 — Publication Binding

Bridge publication SHALL remain the existing Human-triggered path.

Final `RESULT-039.md` SHALL agree with the real operational chain:

```text
TASK_ID: TASK-039
ACTION: RUN
EXECUTOR_ID: codex
EXECUTOR_FAILOVER: NO
HOT_HANDOFF: NO
```

The full repository test suite must exit 0.

M10.3 does not authorize merge. Final merge still requires Human authorization after independent review PASS.

## Decision 13 — Exact Allowed Implementation Scope

Allowed task-branch paths:

```text
scripts/aios_m10_real_dispatch_proof.py
tests/aios_bridge/test_m10_real_dispatch_proof.py
proofs/TASK-039-M10/executor-stage.txt
proofs/TASK-039-M10/recommendation-receipt.txt
proofs/TASK-039-M10/PROOF.json
.ai/results/RESULT-039.md
```

No other implementation path may change.

## Decision 14 — Required Adversarial Coverage

At minimum test:
1. strict receipt parsing and duplicate scalar rejection;
2. wrong task/action/artifact path/blob rejected;
3. wrong status/selected actor rejected;
4. `HUMAN_APPROVAL_REQUIRED != YES` rejected;
5. `AUTHORIZATION_CHANGED != NO` rejected;
6. `LEASE_CHANGED != NO` rejected;
7. wrong/missing/duplicate candidate evidence rejected;
8. wrong capacity state/fingerprint rejected;
9. missing/expired/future capacity evidence rejected;
10. receipt symlink/non-regular/outside-exact-path rejected;
11. capacity mtime after receipt rejected;
12. receipt mtime after authorization rejected;
13. missing/non-ACTIVE/wrong action/wrong executor authorization rejected;
14. authorization artifact/task/branch binding mismatch rejected;
15. missing/mismatched active lease rejected;
16. wrong/missing/tampered executor-stage bytes rejected;
17. policy/request/result fingerprint mismatch rejected;
18. proof semantic tamper retaining old proof fingerprint rejected;
19. exact receipt path only; no history/latest/glob/fuzzy fallback;
20. verifier does not mutate authorization, lease, capacity, or invoke model/provider/executor surfaces.

Tests may use deterministic isolated fixtures. The real proof itself must use the actual local TASK-039 runtime chain.

## Decision 15 — PASS Conditions

M10.3 PASS requires exact evidence of:

```text
fresh HUMAN_DECLARED antigravity QUOTA_EXHAUSTED
fresh HUMAN_DECLARED codex AVAILABLE
  -> real Bridge recommend receipt selects codex
  -> recommendation states HUMAN_APPROVAL_REQUIRED: YES
  -> recommendation states AUTHORIZATION_CHANGED: NO
  -> recommendation states LEASE_CHANGED: NO
  -> Human explicitly approves codex
  -> exact ACTIVE codex RUN authorization
  -> exact active codex ExecutorLease
  -> Codex executor-stage witness
  -> deterministic PROOF.json
  -> Bridge RESULT-039 publication by codex
  -> full repo suite PASS
  -> independent ChatGPT review PASS
```

No stable executor failover or M9 hot handoff is involved.

Upon PASS and Human-authorized merge, M10 is complete. M11 remains separate.
