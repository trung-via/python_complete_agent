# ADR-027 — M10.2 Runtime Capacity Snapshot & Bridge Recommendation Contract Lock

STATUS: LOCKED

## Context

M10.1 / TASK-037 added a pure deterministic zero-token Brain/Executor recommendation engine. M10.2 now connects explicit runtime capacity observations to a Bridge readout surface without changing Human authority.

Baseline:

```text
MAIN_SHA: b1f85034c1b18b3d3526f6ece85afd04cdcdc17e
M10_1_DISPATCH: src/aios_bridge/continuity/dispatch.py
```

## Decision 1 — Recommendation Remains Non-Authority

M10.2 SHALL expose runtime capacity recording/readout and Bridge recommendation only.

It SHALL NOT:
- authorize RUN/FIX;
- acquire/release ExecutorLease;
- mutate authorization state;
- invoke an Executor or Brain;
- start shell/browser/model work;
- publish or merge;
- silently call paid APIs.

A recommendation such as `codex` is evidence only. Human must still explicitly run `bridge.py approve ... --executor codex`.

## Decision 2 — Capacity Observations Live Outside the Worktree

Runtime capacity observations SHALL live under the existing per-workspace runtime root:

```text
<runtime>/dispatch/capacity/<ACTOR_KIND>/<actor_id>.json
```

where `ACTOR_KIND` is exactly `BRAIN` or `EXECUTOR`.

Capacity state is operational runtime state and SHALL NOT dirty Git or become canonical project history.

Each actor gets its own file so independent actor updates cannot overwrite unrelated actors.

## Decision 3 — RuntimeCapacityRecord

Implement a frozen, canonical record with:

```text
schema_version
actor_kind
actor_id
capacity_state
observed_at_epoch_seconds
ttl_seconds
observation_source
record_fingerprint
```

`capacity_state` reuses M10.1 `CapacityState`.

Canonical observation sources for M10.2:

```text
HUMAN_DECLARED
ADAPTER_REPORTED
```

M10.2 SHALL NOT implement vendor quota probing. `ADAPTER_REPORTED` only reserves a provenance value for an already-observed supported integration; no probing/invocation is added by this task.

## Decision 4 — Freshness Is Fail-Safe

A capacity observation is fresh iff:

```text
observed_at_epoch_seconds <= now_epoch_seconds <= observed_at_epoch_seconds + ttl_seconds
```

`ttl_seconds` must be exact int in `[1, 86400]`; bool rejects.

Malformed/future observations fail closed as validation errors.

Missing or expired actor observation SHALL be converted at recommendation time to effective M10.1 state:

```text
UNKNOWN
```

and therefore is not runnable.

The persisted record itself is not rewritten merely because it expired.

## Decision 5 — Policy/Capabilities Are Not Stored in Capacity State

Runtime capacity files SHALL contain only observation/provenance/freshness data.

Actor capability, operation, capacity class, preference and required-capability policy SHALL come from an exact machine-readable marker in the authoritative TASK/REVIEW artifact.

This prevents stale runtime files from becoming hidden architecture/policy configuration and avoids hard-coded vendor branching in Continuity Core.

## Decision 6 — Exact Executor Dispatch Marker

For executor recommendation, authoritative TASK/REVIEW artifacts MAY contain exactly one marker:

```text
DISPATCH_EXECUTOR_POLICY_JSON: <single-line canonical JSON object>
```

The JSON object SHALL contain exactly:

```json
{
  "allow_paid_api": false,
  "candidates": [
    {
      "capacity_class": "SUBSCRIPTION",
      "executor_id": "codex",
      "preference_rank": 1,
      "supported_capabilities": ["FILESYSTEM_WRITE", "LOCAL_GIT", "REPOSITORY_READ", "SHELL", "TEST_EXECUTION"],
      "supported_operations": ["FIX", "RUN"]
    }
  ],
  "operation": "RUN",
  "required_capabilities": ["FILESYSTEM_WRITE", "LOCAL_GIT", "REPOSITORY_READ", "SHELL", "TEST_EXECUTION"]
}
```

Exact requirements:
- one marker only;
- valid UTF-8 JSON object;
- unknown fields reject;
- duplicate actor IDs reject;
- canonical actor IDs only;
- duplicate enum values reject;
- operation must match requested Bridge action;
- no aliases, fuzzy matching or inference from prose;
- policy serialization is bounded.

The artifact marker never grants execution authority.

## Decision 7 — Bridge Recommendation Command

Add read-only command:

```text
bridge.py recommend <task_id> --kind executor --action RUN|FIX
```

For RUN:
- use the exact authoritative TASK artifact.

For FIX:
- use the exact authoritative REVIEW artifact and require actionable `CHANGES_REQUIRED` semantics consistent with existing Bridge FIX rules.

The command SHALL:
1. resolve exact authoritative control artifact using existing Bridge sync/control semantics;
2. parse exactly one `DISPATCH_EXECUTOR_POLICY_JSON` marker;
3. require marker operation == requested action;
4. load each candidate's runtime capacity record by exact actor ID only;
5. map missing/expired records to effective `UNKNOWN`;
6. build existing M10.1 `ExecutorDispatchCandidate` / `ExecutorDispatchRequest`;
7. call `dispatch_executor()`;
8. print deterministic machine-readable recommendation evidence.

It SHALL NOT call `approve`, `handoff`, lease acquisition or execution.

## Decision 8 — Capacity Commands

Add explicit runtime commands:

```text
bridge.py capacity-set --kind executor --actor <id> --state <state> --ttl-seconds <n> [--source HUMAN_DECLARED]
bridge.py capacity-show [--kind executor] [--actor <id>]
```

`capacity-set` records an observation only. It does not imply approval or availability proof beyond the supplied observation.

`capacity-show` is read-only and SHALL display stored state, freshness and effective state.

No command may infer quota from vendor name, product logs, current model, prior RESULT history or wall-clock reset heuristics.

## Decision 9 — Canonical Evidence Output

`recommend` output SHALL include at minimum:

```text
TASK_ID
ACTION
AUTHORIZED_ARTIFACT_PATH
AUTHORIZED_ARTIFACT_BLOB_SHA
POLICY_FINGERPRINT
CAPACITY_OBSERVATION_FINGERPRINTS
DISPATCH_REQUEST_FINGERPRINT
DISPATCH_RESULT_FINGERPRINT
STATUS
SELECTED_EXECUTOR or NONE
HUMAN_APPROVAL_REQUIRED: YES
```

Candidate evaluations SHALL be exposed in deterministic actor-id order, including effective capacity state and M10.1 reason codes.

## Decision 10 — No Hidden Fallback

Missing/expired/corrupt capacity evidence MUST NOT silently select a different actor through undocumented defaults.

- missing/expired -> effective UNKNOWN;
- malformed/corrupt -> command error;
- no runnable compatible candidate -> WAIT/NO_COMPATIBLE from M10.1;
- forbidden PAID_API remains forbidden unless marker explicitly allows it.

Bridge MUST NOT silently default to `antigravity` for recommendation.

Existing `approve` executor defaults are outside M10.2 and are not changed by this task.

## Decision 11 — Generic Runtime Store, Executor Surface First

The runtime capacity record/store SHALL support both `BRAIN` and `EXECUTOR` actor kinds without vendor branching.

TASK-038 only requires the task-bound Bridge recommendation surface for `EXECUTOR`, because this is the immediate operational capacity problem and the M10.3 proof target.

A future Brain readout MAY reuse the same store without changing its schema.

## Decision 12 — Atomic Persistence

Runtime record writes SHALL be fail-closed and atomic at the actor-file boundary:
- create parent directory safely;
- write canonical JSON to a temporary sibling file;
- flush/fsync file;
- `os.replace` into final path;
- no partial final JSON;
- deterministic load validation and fingerprint recheck.

Actor IDs MUST NOT permit path traversal or path separators.

## Decision 13 — Existing Contracts Stay Locked

M10.2 SHALL NOT modify:
- M10.1 ranking semantics;
- Brain/Executor contracts;
- M5 lease semantics;
- M6 stable failover;
- M9 hot handoff;
- RUN/FIX/MERGE Human authority;
- M11 API escape hatch.

## Decision 14 — Required Scenario

The implementation SHALL prove the readout path for:

```text
policy candidates: antigravity, codex
antigravity capacity observation: QUOTA_EXHAUSTED (fresh)
codex capacity observation: AVAILABLE (fresh)
required repo/filesystem/shell/test/local-git capabilities satisfied
allow_paid_api: false
```

Expected:

```text
STATUS: SELECTED
SELECTED_EXECUTOR: codex
HUMAN_APPROVAL_REQUIRED: YES
ACTIVE_AUTHORIZATION_CREATED: NO
EXECUTOR_LEASE_CREATED: NO
```

## Decision 15 — Required Adversarial Coverage

At minimum test:
1. record canonical serialization/fingerprint deterministic;
2. atomic write/read round-trip;
3. actor path traversal/alias rejected;
4. bool/negative/oversized TTL rejected;
5. invalid/future observed time rejected;
6. record fingerprint tamper rejected;
7. missing observation -> effective UNKNOWN;
8. expired observation -> effective UNKNOWN without rewriting record;
9. fresh AVAILABLE preserved;
10. exact marker required; zero/multiple markers reject;
11. malformed/non-object/unknown-field marker reject;
12. duplicate candidate actor IDs reject;
13. operation/action mismatch reject;
14. duplicate capabilities/operations reject;
15. candidate capacity class and preference validation fail closed;
16. exact TASK blob used for RUN recommendation;
17. exact CHANGES_REQUIRED REVIEW blob used for FIX recommendation;
18. control artifact drift fails closed;
19. antigravity exhausted + codex available -> codex recommendation;
20. recommendation does not create auth or lease;
21. WAIT does not auto-approve or fall through to forbidden PAID_API;
22. capacity-set does not mutate Git worktree;
23. capacity-show/recommend are read-only with respect to authorization/lease stores;
24. existing approve/publish/lease/failover/hot-handoff tests remain green.

## Acceptance Criteria

M10.2 PASS requires:
- generic external runtime capacity store implemented;
- exact task/review executor policy parsing;
- read-only Bridge recommendation surface implemented;
- stale/missing capacity fail-safe to UNKNOWN;
- required real-shaped Codex recommendation scenario green;
- full repository suite exit 0;
- zero automatic RUN/FIX authorization;
- zero automatic lease mutation;
- zero provider/API quota probing.

M10.2 does NOT itself prove a real human operational selection/publication chain. That is M10.3.
