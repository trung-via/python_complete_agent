## Audit Finding Driving M11.3B

The current MiniMax-M3 local counter validates:

```text
local manifest source_repository/source_revision/path fields
local file SHA-256 == SHA-256 declared by that manifest
```

This proves local file/manifest consistency, but the manifest currently supplies its own asset digests. For the real paid proof, this is insufficient as provenance authority because a replaced manifest plus replaced files can remain internally consistent.

M11.3B therefore introduces a separate canonical `MiniMaxM3ProofLock` whose Git blob SHA is verified by Bridge from canonical control state. The local manifest and local bytes must both match that independently authorized lock.

```text
CANONICAL_GIT_BOUND_PROOF_LOCK
        ↓ exact expected digests
LOCAL_MANIFEST
        ↓ exact same digests
LOCAL_TEMPLATE / LOCAL_TOKENIZER
        ↓ re-hash exact
TRUSTED_COUNTER CONSTRUCTION
```

`asset-manifest.json` remains a local integrity receipt. It is NOT the provenance root.

Do not silently infer or migrate endpoint values.

### Lock Serialization

- exact field set only;
- duplicate JSON keys rejected;
- strict UTF-8;
- bool-as-int rejected where applicable;
- digests lowercase 64-hex;
- canonical JSON uses `sort_keys=True`, compact separators, `ensure_ascii=False`;
- deterministic SHA-256 `fingerprint()`;
- bounded serialized size;
- no API key value, prompt, context, output, cookie, authorization header, local absolute path, timestamp, or machine identity.
