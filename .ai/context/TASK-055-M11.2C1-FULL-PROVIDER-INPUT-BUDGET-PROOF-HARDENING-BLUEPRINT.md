## Why this hardening is required

M11.2C is merged and correctly enforces ACTIVE grant binding, single paid candidate selection, subscription preference, consume-before-gateway, one-shot replay closure, and no retry.

Independent pre-M11.3 audit found one remaining budget-proof gap:

- `ContextBuildResult.counted_tokens` is produced by `ContextBuilder` over selected `ContextItem` renderings only.
- `render_messages(ModelRequest)` adds provider input outside those context items: system governance prompt, Task ID framing, instruction framing, context section framing, and output requirements.
- `MiniMaxOpenAIProvider` renders those messages and sends them to the provider.
- `ModelRequest.max_input_tokens` is metadata; the MiniMax adapter does not send/enforce it as a provider-side input cap.

Therefore an exact context-only count is not sufficient evidence that the complete provider input is within the Human paid grant.

ADR-036 requires exact pre-call input-token compliance. M11.3 MUST NOT begin until this gap is closed fail-closed.

## Decision

Add a separate full-provider-input count seam. Do NOT redefine `ContextBuilder` semantics.

The runtime must distinguish:

```text
ContextBuildResult
  = deterministic context selection/budget evidence

ProviderInputCountEvidence
  = exact token count of the COMPLETE ModelRequest as it will be rendered for the selected provider/model
```

Before any request with `allow_paid_api=True` is constructed, M11.2C coordinator must prove:

```text
provider_input_count.token_count_is_exact == True
provider_input_count.provider_id == grant.provider_id
provider_input_count.model_id == grant.model_id
provider_input_count.model_request_fingerprint == exact fingerprint(model_request)
provider_input_count.counted_input_tokens <= model_request.max_input_tokens
model_request.max_input_tokens <= grant.max_input_tokens
model_request.max_output_tokens <= grant.max_output_tokens
```

The existing exact ContextBuildResult checks remain. This is an additional proof, not a replacement.

### Exact immutable evidence contract

Implement semantics equivalent to:

```python
@dataclass(frozen=True)
class ProviderInputCountEvidence:
    provider_id: str
    model_id: str
    model_request_fingerprint: str
    counted_input_tokens: int
    counter_id: str
    token_count_is_exact: bool
    schema_version: str = "1"
```

Validation:
- exact schema version `1`;
- provider/model/counter IDs exact non-empty unpadded strings;
- request fingerprint exact lowercase SHA-256;
- counted_input_tokens exact non-negative int, bool rejected;
- token_count_is_exact exact bool;
- deterministic `to_dict()` / canonical JSON if implemented;
- no secrets, request body, or raw prompt stored in evidence.

### ModelRequest fingerprint

Provide one canonical helper equivalent to:

```python
fingerprint_model_request(request: ModelRequest) -> str
```

It MUST SHA-256 the canonical UTF-8 JSON of `request.to_dict()` with sorted keys, compact separators, and `ensure_ascii=False`.

No credentials or provider runtime secrets are part of the ModelRequest fingerprint.

### Counter protocol

Define a runtime-checkable interface/Protocol equivalent to:

```python
class ProviderInputTokenCounter(Protocol):
    @property
    def provider_id(self) -> str: ...
    @property
    def model_id(self) -> str: ...
    @property
    def counter_id(self) -> str: ...
    @property
    def is_exact(self) -> bool: ...
    def count_request(self, request: ModelRequest) -> ProviderInputCountEvidence: ...
```

TASK-055 does NOT implement the real MiniMax tokenizer counter. Tests use deterministic offline fake counters.

No counter accepted by the paid coordinator may perform network I/O. Real MiniMax local exact counter comes in the next subtask.

No token counter call after paid enablement is needed.

### Counter authority restrictions

The coordinator MUST reject before paid enablement if:

```text
counter provider mismatch
counter model mismatch
counter counter_id invalid
counter is_exact != True
evidence provider/model/counter mismatch
evidence token_count_is_exact != True
evidence request fingerprint mismatch
evidence count negative/non-int
full provider input count > ModelRequest.max_input_tokens
```

A caller-created ContextBuildResult with `token_count_is_exact=True` is no longer sufficient on its own.

### Network prohibition

TASK-055 counter contract is intended for local deterministic counting.

Production hardening code MUST NOT:
- call MiniMax/OpenAI/Anthropic/Gemini token-count endpoints;
- read API keys;
- use HTTP/network;
- download tokenizer assets;
- initialize a real paid provider;
- perform any real provider call.

TASK-056 will implement a pinned local MiniMax M3 counter against provider-official tokenizer assets.
