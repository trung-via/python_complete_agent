## Purpose

Implement the runtime coordinator that turns one already-ACTIVE Human paid-API Brain grant into one bounded M10 paid-Brain escape opportunity.

This milestone is runtime wiring only. Tests may use fake providers/gateways. No real paid provider call is authorized by TASK-053.

## Locked Architecture

```text
base BrainDispatchRequest (allow_paid_api = false)
        +
exact ACTIVE PaidApiGrant
        +
exact canonical artifact/context binding
        +
exact ModelRequest + ContextBuildResult
        +
configured ModelGateway
        ↓
validate one and only one PAID_API Brain candidate == grant.brain_id
        ↓
validate task/workspace/brain/provider/model/operation/artifact/token bounds
        ↓
require exact input counter evidence
        ↓
derive NEW BrainDispatchRequest(allow_paid_api = true)
        ↓
M10 dispatch_brain()
        ↓
SUBSCRIPTION Brain wins? → return recommendation; grant remains ACTIVE; gateway not called
        ↓ no

        ↓
AtomicPaidApiGrantStore.consume(grant) DURABLY
        ↓
ModelGateway.invoke(...) exactly once
        ↓
return validated GatewayResult
```

The coordinator never mutates the incoming dispatch request.

## Why exactly one PAID_API Brain candidate

`BrainDispatchRequest.allow_paid_api` is request-wide. Enabling it would otherwise make every compatible PAID_API candidate eligible. M11 authorization is grant-specific, not class-wide.

Therefore before deriving `allow_paid_api=true`:

```text
PAID_API_CANDIDATE_COUNT: exactly 1
PAID_API_CANDIDATE_BRAIN_ID: exactly grant.brain_id
PAID_API_EXECUTOR: impossible / rejected by type boundary
```

Any second PAID_API Brain candidate fails closed before dispatch and before grant consumption.

### Exact operation mapping

Continuity and External Brain operation enums differ. Lock this explicit mapping:

```text
continuity.PLAN           -> external.PLAN
continuity.DIAGNOSIS      -> external.DIAGNOSE_FAILURE
continuity.PATCH_PROPOSAL -> external.GENERATE_PATCH
continuity.REVIEW         -> external.REVIEW_PATCH
```

These continuity operations are NOT supported by the current External Brain contract and must fail closed:

```text
TASK
TASK_AND_PLAN
```

Never infer or alias them to PLAN.

Require:

```text
grant.brain_operation == base_dispatch_request.operation
model_request.operation == mapped external operation
```

### Task / provider / model / workspace binding

Use existing `validate_paid_api_grant_binding()` semantics and require exact:

```text
model_request.task_id == grant.task_id
grant_store.workspace_id == grant.workspace_id
paid candidate brain_id == grant.brain_id
model_request.provider == grant.provider_id
model_request.model == grant.model_id
gateway.provider.provider_id == grant.provider_id
```

For M11 v1, configured provider model identity must also be mechanically available before consume:

```text

```

If configured model identity is unavailable, fail closed before consume. Do not expand `ProviderAdapter` protocol in TASK-053.

### Authorized artifact must actually be in paid context

Require:

```text
authorized_artifact.path == grant.authorized_artifact_path
authorized_artifact.blob_sha == grant.authorized_artifact_blob_sha
```

Then require exactly one selected `ContextItem` in `context_build.selected` / `model_request.context` whose `path` equals the authorized artifact path.

Compute the Git SHA-1 blob object ID from the exact UTF-8 context content:

```text
sha1(b"blob " + decimal_byte_length + b"\0" + utf8_content)
```

and require it to equal `grant.authorized_artifact_blob_sha`.

Rationale: a grant bound to one canonical control blob must not authorize a request whose actual model context contains different bytes under the same path.

No Git subprocess or filesystem fallback is needed for this check.

### Context correlation and exact budget proof

Require before consume/provider call:

```text
model_request.context == context_build.selected
context_build.token_count_is_exact is True
context_build.counter_id is exact non-empty str
model_request.max_input_tokens is exact positive int, not None
model_request.max_output_tokens is exact positive int, not None
context_build.max_context_tokens == model_request.max_input_tokens
context_build.counted_tokens + context_build.protocol_reserve_tokens <= context_build.max_context_tokens
```

Then enforce the Human grant envelope with existing M11.1 budget semantics:

```python
validate_paid_api_grant_budget(
    grant,
    input_tokens=model_request.max_input_tokens,
    output_tokens=model_request.max_output_tokens,
)
```

If `token_count_is_exact == false`, fail closed even when a conservative estimate is below the grant.

TASK-053 must not claim provider post-call usage as pre-call proof.

## Selection Outcomes

### No selected paid Brain

If M10 returns WAIT / NO_COMPATIBLE_CANDIDATE, or selects a SUBSCRIPTION Brain:

```text
grant remains ACTIVE
grant_store.consume not called
gateway.invoke not called
gateway_result = None
grant_consumed = false
paid_candidate_selected = false
```

A runnable subscription selection is not executed by TASK-053; this coordinator only owns the paid escape seam.

### Paid Brain selected

Require exact selected actor:

```text
dispatch_result.selected_actor_id == grant.brain_id
```

Then and only then:

```python
grant_store.consume(grant, now_epoch_seconds=now)
```

must complete successfully before:

```python
await gateway.invoke(model_request, context_build=context_build)
```

No provider call may begin before durable consume.

## Consume-Before-Call Failure Semantics

```text
consume fails                  -> provider call count 0
consume succeeds, gateway raises -> grant remains CONSUMED; no restore; no retry
provider returns failure       -> grant remains CONSUMED; no retry
ledger_persisted == false      -> grant remains CONSUMED; no retry
second concurrent/replay call  -> loses consume race and fails before gateway
```

Once consume succeeds, ACTIVE must never be recreated by this module.

## No-Retry / No-Failover Rule

The coordinator may call `gateway.invoke` at most once.

Forbidden:

```text
retry loop
second gateway
second provider
fallback paid model
grant refresh
re-activate grant
auto-create new grant
auto Executor invocation
auto patch application
```
