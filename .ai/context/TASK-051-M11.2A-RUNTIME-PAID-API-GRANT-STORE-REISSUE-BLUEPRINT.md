## One-Shot Safety Model

A grant authorizes at most one provider-call ATTEMPT.

Later wiring will enforce:

```text
ACTIVE
  ↓ exact binding + exact pre-call budget + unexpired validation
CONSUMED DURABLY
  ↓
provider call may start
```

If process crashes after durable consume but before provider invocation, the grant remains CONSUMED and is never reusable.

TASK-051 itself performs no provider call.

## ACTIVE / CONSUMED Exclusivity

For one `(task_id, grant_id)` key:

```text
ACTIVE missing + CONSUMED missing = never seen
ACTIVE only                       = potentially usable
CONSUMED only                     = terminal/replay closed
ACTIVE + CONSUMED                 = corruption → fail closed
```

No automatic repair.

`activate()` rejects if either ACTIVE or CONSUMED already exists for that key. A consumed `grant_id` can never be reactivated even with different semantics.

## Strict Load Semantics

`load_active()` / `load_consumed()` return None only when requested state is absent AND there is no contradictory sibling state.

Raise `ContinuityStateValidationError` for:
- state path is directory;
- empty state;
- oversized state;
- invalid UTF-8 / malformed JSON;
- invalid `PaidApiGrant`;
- wrong task_id;
- wrong grant_id;
- wrong workspace_id;
- stale/forged fingerprint;
- ACTIVE+CONSUMED dual-state corruption.

Read at most `MAX_SERIALIZED_BYTES + 1` bytes.

Translate `ValueError` from `PaidApiGrant.from_json()` into `ContinuityStateValidationError` without logging raw grant contents.

## Atomic Activation

`activate()` MUST:
1. require exact `PaidApiGrant` type;
2. validate store workspace match;
3. validate `now_epoch_seconds` and unexpired grant;
4. acquire task-scoped cross-thread + cross-process mutation guard;
5. fail if ACTIVE or CONSUMED already exists;
6. persist exact `grant.to_canonical_json().encode("utf-8")` using exclusive creation;
7. fully write + fsync file;
8. best-effort fsync parent directory where supported;
9. strict read-back and prove exact equality/fingerprint;
10. return grant.

Failed activation may clean only state created by that exact call. Never delete pre-existing state.

## Atomic Consume

`consume()` MUST:
1. require exact `PaidApiGrant` type;
2. validate time;
3. acquire same task-scoped mutation guard;
4. strict-load ACTIVE and require exact equality/fingerprint/workspace;
5. require still unexpired;
6. require CONSUMED destination absent;
7. atomically move ACTIVE to CONSUMED in same task namespace;
8. best-effort fsync affected directories;
9. strict-load CONSUMED and prove exact equality/fingerprint;
10. prove ACTIVE absent;
11. return consumed grant.

After atomic move succeeds, any later verification failure MUST leave grant terminal in CONSUMED. Never recreate ACTIVE.
