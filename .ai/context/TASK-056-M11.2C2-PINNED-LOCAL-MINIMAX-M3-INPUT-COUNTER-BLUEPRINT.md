## Why this task exists

TASK-055 merged the full-provider-input proof seam and deliberately left production trusted counter types empty. M11.3 remains blocked until one audited local counter can produce exact full-input evidence for the existing MiniMax-M3 OpenAI-compatible provider without any token-count network call.

Current External Brain wire construction is deterministic:

```text
ModelRequest
  -> external_brain.prompt.render_messages()
  -> [system text, user text]
  -> MiniMaxOpenAIProvider messages payload
```

MiniMax-M3's official chat template adds provider-side framing beyond those two messages. In particular, an OpenAI-role `system` message is mapped into the template's developer slot while the template also emits its own root-system/model identity + thinking instructions. A counter that tokenizes only the two raw message strings would undercount.

## Specialized MiniMax-M3 prompt rendering

Do NOT implement the full 247-line Jinja engine. The paid escape currently sends a deliberately narrow text-only shape, so TASK-056 must implement and validate only the exact supported subset.

### Supported input shape

`render_messages(model_request)` must return exactly:

```text
[
  {"role": "system", "content": <str>},
  {"role": "user",   "content": <str>}
]
```

No third message, assistant history, tools, images, video, multipart content, developer/root role, or tool-call structure is authorized by TASK-056.

Anything outside this exact shape MUST fail closed before tokenization.

### Pinned template semantics for this shape

For the two-message shape above, the official MiniMax-M3 template at the pinned revision behaves as follows:

1. The incoming OpenAI `system` message is treated as `developer_message`.
2. Because no `root` message exists, the template emits its default MiniMax root-system/model identity.
3. The template appends its thinking instructions; with no explicit `thinking_mode`, the template uses adaptive semantics.
4. It emits the developer slot containing the AIOS system message.
5. It emits the user slot containing the AIOS user message.
6. `add_generation_prompt=True` emits the `ai` generation prefix.
7. No tools are supplied.

Special token strings are pinned from the official template:

```text
NS_TOKEN:  ]<]minimax[>[
BOD_TOKEN: ]~!b[
BOS_TOKEN: ]~b]
EOS_TOKEN: [e~[
THINK_BEGIN_TOKEN: <mm:think>
THINK_END_TOKEN: </mm:think>
```

The specialized renderer MUST match the pinned template's exact whitespace/newline behavior for this supported shape. The rendered provider prompt is internal transient data only and MUST NOT be persisted in `ProviderInputCountEvidence`, logs, RESULT artifacts, or safe receipts.

## Exact tokenization
