## Objective

This task is storage/state-transition work only. It MUST NOT create a Human Bridge command, set `BrainDispatchRequest.allow_paid_api`, invoke dispatch, read provider credentials, invoke ModelGateway, or call a provider.

## Safety Model

A paid API grant authorizes at most one provider-call ATTEMPT.

The runtime transition required by later wiring is:

```text
ACTIVE
  ↓ exact binding + exact pre-call budget + unexpired validation
CONSUMED  ← durable transition MUST happen before provider invocation
  ↓
provider call may start exactly once
```

Therefore, if the process crashes after durable consume but before a provider call starts, the grant remains CONSUMED and MUST NOT be reusable. Losing one authorization is acceptable; risking a second paid call is not.

TASK-050 itself performs no provider call. It only implements the store primitive needed to enforce this boundary later.

## Store Type

Implement:

```python
class AtomicPaidApiGrantStore:
    def __init__(self, grant_root: Path | str, workspace_id: str) -> None: ...

    def load_active(self, task_id: str, grant_id: str) -> PaidApiGrant | None: ...
    def load_consumed(self, task_id: str, grant_id: str) -> PaidApiGrant | None: ...

    def activate(
        self,
        grant: PaidApiGrant,
        *,
        now_epoch_seconds: int,
    ) -> PaidApiGrant: ...

    def require_active(
        self,
        expected: PaidApiGrant,
        *,
        now_epoch_seconds: int,
    ) -> PaidApiGrant: ...

    def consume(
        self,
        expected: PaidApiGrant,
        *,
        now_epoch_seconds: int,
    ) -> PaidApiGrant: ...
```

No method may read the wall clock internally. Callers supply `now_epoch_seconds` explicitly so tests and security decisions are deterministic.

## Namespace / File Layout

The store root is external runtime state supplied by the caller. TASK-050 does not modify `bridge.py` or `get_runtime_paths()` yet.

Per-task layout:

```text
<grant_root>/TASK-N/
    .paid_api_grant_mutation.lock
    active/
        <grant-key>.json
    consumed/
        <grant-key>.json
```

`grant-key` MUST be a path-safe deterministic lowercase SHA-256 of the exact UTF-8 `grant_id` string:

```python
sha256(grant_id.encode("utf-8")).hexdigest()
```

Do NOT place raw `grant_id` into filenames because the M11.1 identifier contract permits characters such as `:` that are invalid in Windows filenames.

The loaded record MUST still prove exact `task_id`, exact `grant_id`, exact `workspace_id`, and valid fingerprint. The hashed filename is only a namespace key, never authority.

## Exact Runtime Validation

### Exact ints

`now_epoch_seconds`:
- exact `int`;
- bool rejected;
- non-negative.

### Expiry

A grant is usable only when:

```text
now_epoch_seconds < grant.expires_at_epoch_seconds
```

At exact equality it is expired and MUST fail closed.

No grace period, clock skew normalization, or default current time.

### Workspace

Store constructor requires exact lowercase 64-hex `workspace_id`.

Every activated/loaded/required/consumed grant MUST have:

```text
grant.workspace_id == store.workspace_id
```

Mismatch fails closed.

### ACTIVE / CONSUMED exclusivity

For one `(task_id, grant_id)` key:
- both ACTIVE and CONSUMED missing = never seen;
- ACTIVE only = eligible for exact validation if unexpired;
- CONSUMED only = terminal and non-reusable;
- both ACTIVE and CONSUMED present = corruption and MUST fail closed.

No automatic repair.

### Replay

`activate()` MUST reject when either:
- the exact grant key is already ACTIVE; or
- the exact grant key already exists in CONSUMED history.

A consumed `grant_id` may never be reactivated, even if a caller presents different grant semantics with the same `grant_id`.

## Strict Load Semantics

`load_active()` and `load_consumed()` return `None` only when the requested state file does not exist and there is no contradictory sibling state.

If a discovered state path is:
- directory instead of file;
- empty;
- oversized;
- invalid UTF-8 / malformed JSON;
- invalid `PaidApiGrant`;
- namespace mismatched by task_id or grant_id;
- workspace mismatched;
- stale/forged fingerprint;
- duplicated in ACTIVE + CONSUMED;

then raise `ContinuityStateValidationError` fail-closed.

Read at most `MAX_SERIALIZED_BYTES + 1` bytes.

Translate lower-level `ValueError` from `PaidApiGrant.from_json()` into `ContinuityStateValidationError` without exposing secrets or raw grant contents.

## Atomic Activation

`activate()` MUST:

1. require exact `PaidApiGrant` type;
2. validate store workspace match;
3. validate `now_epoch_seconds` and require unexpired grant;
4. acquire a task-scoped cross-thread + cross-process mutation guard;
5. fail if ACTIVE or CONSUMED state already exists for the key;
6. persist canonical grant JSON with exclusive creation (`O_CREAT | O_EXCL` or equivalent);
7. write all bytes and `fsync` the file;
8. best-effort fsync parent directory where supported;
9. read back via strict loader and prove exact equality + fingerprint;
10. return the activated grant.

Partial failed activation owned by the current call may be cleaned up. Never delete pre-existing state.

## Atomic Consume

`consume()` is the security-critical one-shot transition.

It MUST:

1. require exact `PaidApiGrant` type;
2. validate supplied `now_epoch_seconds`;
3. acquire the same task-scoped mutation guard;
4. strict-load ACTIVE and require exact equality/fingerprint/workspace;
5. require the ACTIVE grant is still unexpired at consume time;
6. require CONSUMED destination absent;
7. atomically move ACTIVE state into CONSUMED state in the same task namespace;
8. best-effort fsync affected directories where supported;
9. strict-load CONSUMED and prove exact equality/fingerprint;
10. prove ACTIVE no longer exists;
11. return the consumed grant.

No provider call occurs inside `consume()`.

After successful consume, a second `consume()` or `require_active()` for the same grant MUST fail before any external side effect.

The store MUST NOT recreate ACTIVE state if anything fails after the atomic move. Once the move has occurred, fail closed and leave the grant terminal rather than risking reuse.

## `require_active()` Exactness

`require_active(expected, now_epoch_seconds=...)` MUST:
- require exact `PaidApiGrant` type;
- strict-load ACTIVE by expected task_id/grant_id;
- reject missing ACTIVE;
- reject any CONSUMED sibling;
- reject expiry;
- require stored grant equals the expected grant exactly;
- require stored fingerprint equals `expected.fingerprint()`;
- require exact workspace match.

No defaulting or semantic reconstruction.

## Locking

Implement a private task-scoped mutation guard analogous in safety to the existing Executor lease store:
- in-process re-entrant lock per canonical task_id;
- OS-level file lock on `.paid_api_grant_mutation.lock`;
- Windows via `msvcrt`, POSIX via `fcntl`;
- all activation/consume transitions for a task serialized through this guard.

Do not import or depend on private helpers from `runtime_lease.py`.
