## Purpose

Prepare M11.3 for exactly one real Human-authorized MiniMax paid Brain call without spending any API quota in this task.

The existing coordinator already computes exact full-provider-input evidence before paid enablement, but that evidence is currently local to `execute_paid_api_brain_escape()` and is not returned in `PaidApiBrainEscapeResult`. M11.3 therefore cannot later prove:

```text
LOCAL_PRECALL_COUNT == PROVIDER_REPORTED_INPUT_TOKENS
```

without calling the counter a second time. Re-counting after the paid call is forbidden as proof authority.

TASK-058 must expose the ORIGINAL pre-call evidence object through the coordinator result and add a pure/offline verifier that creates a bounded immutable operational proof receipt from already-produced runtime evidence.

## Locked M11.3 Sequence

```text

```

It must be the exact evidence produced by the one existing `count_request(model_request)` invocation inside `execute_paid_api_brain_escape()`.

Rules:

```text

```

Any normal return from `execute_paid_api_brain_escape()` occurs only after provider input evidence has already been produced and validated, so the result field is required rather than optional. This remains true when a subscription Brain wins dispatch and no paid call occurs.

Do not move the counter later in the flow. Preserve its current position before paid enablement / dispatch.

```text
gateway_result is exact GatewayResult
```

### Exact Input-Token Correlation — Critical Proof

```text

    == gateway_result.response.input_tokens
    == gateway_result.usage_record.provider_input_tokens
```

This equality is the operational validation of the pinned local MiniMax-M3 template/tokenizer correspondence.

A mismatch is terminal proof failure for that grant. No tolerance, estimate band, cache adjustment, or second count.

## Receipt Contract

The receipt must contain only bounded metadata/evidence, never prompt/context/output text, API key, headers, cookies, raw provider body, tokenizer bytes, or template bytes.

Required semantic fields should include at minimum:

```text
schema_version = 1
task_id
grant_id
grant_fingerprint
brain_id
provider_id
model_id
request_id
model_request_fingerprint
authorized_artifact_path
authorized_artifact_blob_sha

local_pre_call_input_tokens

provider_reported_output_tokens
provider_request_id
response_status
ledger_persisted = true
grant_consumed = true
input_token_match = true
response_content_sha256
```

`response_content_sha256` binds the receipt to the exact validated proposal without persisting its content.

Receipt must:
- be `@dataclass(frozen=True)`;
- reject bool-as-int;
- validate exact field types and bounded non-empty identifiers;
- validate lowercase SHA-256 / Git blob formats where applicable;
- serialize deterministic canonical JSON (`sort_keys`, compact separators, UTF-8 semantics);
- provide deterministic SHA-256 receipt fingerprint over semantic fields;
- contain no wall-clock field in M11.3A.
